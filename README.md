# Bybit TradingView Bot

Бот открывает и закрывает позиции на Bybit (USDT-перпетуалы) по сигналам из алертов TradingView.

- Плечо, размер позиции, TP/SL и список пар задаются в одном файле `config.yaml`.
- По умолчанию работает на **демо-счёте Bybit**: виртуальные деньги, без риска. Переход на реальный счёт описан [ниже](#переход-на-реальный-счёт).
- Публичный адрес для TradingView даёт встроенный бесплатный туннель, поэтому для пробы не нужны VPS и домен.

```
Алерт TradingView ──► webhook бота ──► проверка secret ──► ордер на Bybit
```

Сигнал `long` или `short` открывает позицию. Если открыта противоположная, бот сначала её закрывает (это настраивается). Сигнал `close` закрывает позицию.

## Запуск на демо-счёте (≈10 минут)

Нужен [Docker](https://docs.docker.com/get-docker/).

### 1. Demo API-ключ Bybit
1. Войдите на [bybit.com](https://www.bybit.com), наведите курсор на иконку профиля и выберите **Demo Trading**. Если пункта там нет, он есть в верхнем меню **Tools**.
2. Уже в демо-режиме: иконка профиля → **API** → **Create New Key** → **System-generated API Keys**.
3. Права: **Read-Write**, **Contracts / Unified Trading → Orders, Positions**. Вывод средств (Withdraw) **не включайте**.
4. Сохраните API Key и API Secret. Secret показывается только один раз.

На демо-счёте уже есть виртуальные USDT.

### 2. Настройки
```bash
cp config.example.yaml config.yaml
openssl rand -hex 24      # готовый секрет для webhook
```
В `config.yaml` впишите ключи Bybit, вставьте сгенерированную строку в `webhook.secret` и настройте пары. Все параметры описаны в комментариях внутри файла.

### 3. Запуск
```bash
docker compose up -d --build
docker compose logs bot                     # баланс и настройки каждой пары
docker compose logs tunnel | grep lhr.life  # публичный адрес
```
Публичный адрес выглядит так: `https://xxxx.lhr.life`. Адрес webhook для TradingView: `https://xxxx.lhr.life/webhook`.

> Адрес меняется при каждом перезапуске туннеля. После перезапуска обновите его в алерте TradingView. Компьютер не должен уходить в сон.

### 4. Проверка без TradingView
```bash
docker compose exec bot python tools/send_test_signal.py long BTCUSDT --url https://xxxx.lhr.life/webhook
docker compose exec bot python tools/send_test_signal.py close BTCUSDT --url https://xxxx.lhr.life/webhook
docker compose logs bot
```
В журнале появятся строки `открыт LONG` и `закрыт LONG`, а сделка будет видна в Demo Trading на Bybit.

### 5. Алерт в TradingView
Для webhook-алертов нужен платный тариф TradingView с включённой 2FA.

В окне создания алерта:
- **Notifications → Webhook URL:** `https://xxxx.lhr.life/webhook`
- **Message:** один из шаблонов ниже. Значение `secret` должно совпадать с `config.yaml`.

**Индикатор:** отдельный алерт на каждое действие (`long`, `short` или `close`).
```json
{"secret": "ваш-секрет", "symbol": "{{ticker}}", "action": "long"}
```

**Стратегия (Pine `strategy`):** один алерт на все действия.
```json
{"secret": "ваш-секрет", "symbol": "{{ticker}}", "action": "{{strategy.market_position}}", "id": "{{strategy.order.id}}-{{timenow}}"}
```
`flat` означает «закрыть позицию». Поле `id` защищает от повторного исполнения одного и того же сигнала. Тикеры вида `BYBIT:BTCUSDT.P` бот понимает сам.

## Переход на реальный счёт

TradingView и алерты остаются прежними. Меняется только сторона Bybit.

1. В **обычном** (не демо) режиме Bybit создайте API-ключ с теми же правами, без вывода средств. Если у сервера постоянный IP, привяжите ключ к нему.
2. Переведите USDT на Unified-счёт.
3. В `config.yaml` поставьте `mode: live`, впишите новые ключи и для начала задайте минимальный размер позиции.
4. Перезапустите бота: `docker compose up -d`. В журнале должна появиться строка `Режим: LIVE` и реальный баланс.

Ключ из Demo Trading с `mode: live` не работает, и наоборот.

### Почему для реальной торговли нужен VPS

VPS — это арендованный сервер, который работает круглосуточно. Для реальных денег он нужен по нескольким причинам:
- **Сигналы не теряются.** Домашний компьютер засыпает, перезагружается и теряет интернет. Сигнал, пришедший в это время, пропадёт, в том числе сигнал на закрытие позиции.
- **Постоянный адрес.** Бесплатный туннель меняет адрес при перезапуске и может оборваться. У VPS адрес постоянный, туннель не нужен.
- **Безопасность ключа.** API-ключ Bybit можно привязать к постоянному IP сервера. Тогда украденный ключ с другого адреса работать не будет.

**Где взять.** Хватит самого простого тарифа: 1 vCPU, 1–2 ГБ RAM, Ubuntu 24.04. Это примерно 5 $ в месяц у [Hetzner](https://www.hetzner.com/cloud), [DigitalOcean](https://www.digitalocean.com) или [Vultr](https://www.vultr.com). Сервер лучше взять в Европе (Германия, Нидерланды, Финляндия). Не берите сервер в США: Bybit ограничивает доступ из ряда стран, в том числе из США. Актуальный список есть в правилах Bybit.

Развёртывание на VPS (свой домен и HTTPS) я настраиваю отдельно — напишите, если нужно.

## Настройки

| Параметр | Значения |
|---|---|
| `mode` | `demo`: демо-счёт, `live`: реальный счёт |
| `margin_mode` | `isolated` / `cross` (для всего аккаунта) |
| `leverage` | плечо, от 1 до максимума Bybit для пары |
| `size.mode` | `margin_usdt`: маржа в USDT · `notional_usdt`: объём позиции в USDT · `balance_pct`: % баланса как маржа · `qty`: количество монет |
| `take_profit_pct` / `stop_loss_pct` | TP/SL в % от цены входа, `null` означает без TP/SL |
| `on_opposite` | `reverse`: перевернуть позицию · `close`: только закрыть · `ignore`: игнорировать |
| `symbols` | разрешённые пары; для каждой можно переопределить любую настройку |

После изменения `config.yaml` перезапустите бота: `docker compose restart bot`.

Количество монет округляется по правилам Bybit. Например, при марже 20 USDT и плече x5 позиция BTC выйдет около 80–100 USDT, потому что объём BTC берётся с шагом 0.001.

## Если что-то не работает

Все ошибки бот пишет понятным текстом в `docker compose logs bot`.

| Сообщение | Что сделать |
|---|---|
| `Bybit отклонил API-ключ` | Проверьте ключи и `mode`: демо-ключ работает только с `demo`, ключ реального счёта — только с `live`. |
| `Системные часы спешат…` | Включите синхронизацию времени: `sudo timedatectl set-ntp true` (Linux) или «Установить время автоматически» в Windows/macOS. |
| Ошибка в `webhook.secret` | Секрет должен состоять из латиницы, цифр и знаков, без пробелов. Сгенерируйте его командой `openssl rand -hex 24`. |
| Тестовый сигнал отвечает `401` | Значение `secret` в запросе не совпадает с `config.yaml`. |
| Адрес `lhr.life` не открывается | Перезапустите туннель (`docker compose restart tunnel`) и возьмите новый адрес из логов. |

## Безопасность и ограничения
- Ключ создаётся без права вывода средств, поэтому бот не может вывести деньги.
- Запросы без правильного `secret` отклоняются. Не передавайте секрет третьим лицам.
- Сигналы исполняются строго по очереди, по одному.
- Поддерживаются USDT-перпетуалы, Unified-аккаунт, режим позиции one-way и рыночные ордера.

Устройство кода описано в [architecture.md](architecture.md), решения записаны в [docs/adr](docs/adr).
