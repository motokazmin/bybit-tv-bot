# 0001. Webhook отвечает сразу, ордера исполняет фоновый воркер по очереди

## Контекст
TradingView ждёт ответ на webhook около 3 секунд и не гарантирует порядок и единственность доставки.
Исполнение сигнала — это несколько вызовов Bybit (позиция, плечо, ордер, при развороте два ордера). Вместе они могут занять больше времени.
Если два сигнала по одной паре исполнять параллельно, возможна гонка: оба увидят «позиции нет» и откроют две.

## Решение
- Webhook только проверяет secret и формат, отсекает дубли по `id` и кладёт `Signal` в `asyncio.Queue`, после чего отвечает 200.
- Один воркер забирает сигналы по одному и исполняет `Trader.handle` в потоке (`asyncio.to_thread`), потому что pybit синхронный.
- Дубли отслеживаются в памяти (последние 1000 id).

## Последствия
- TradingView всегда получает быстрый ответ.
- Сигналы исполняются строго последовательно, гонок нет. Для одного аккаунта и десятков сигналов в минуту пропускной способности достаточно.
- Результат исполнения не возвращается в HTTP-ответе, его видно в журнале.
- Очередь и список id теряются при перезапуске. Для MVP это допустимо. Если понадобится гарантированная доставка, очередь нужно будет хранить в SQLite.
