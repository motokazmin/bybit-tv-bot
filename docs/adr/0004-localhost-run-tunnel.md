# 0004. Демо-туннель через localhost.run вместо Cloudflare Quick Tunnel

## Контекст
TradingView шлёт webhook со своих серверов, поэтому боту на ноутбуке нужен публичный HTTPS-адрес.
Изначально использовался `cloudflared` (Quick Tunnel, `*.trycloudflare.com`). В моей сети туннель
регистрировался, но через несколько секунд трафик переставал проходить: Cloudflare отвечал 502/530 (ошибка 1033)
и на QUIC, и на HTTP/2, при том что предпроверки cloudflared проходили. Вероятно, соединения к Cloudflare
режутся на уровне сети провайдера — кодом это не лечится.

## Решение
- Сервис `tunnel` в `docker-compose.yml` — обычный SSH reverse-туннель на localhost.run
  (`ssh -R 80:bot:8000 nokey@localhost.run`), адрес вида `https://xxxx.lhr.life`. Без регистрации и ключей.
- Туннель — только для демонстрации. Для постоянной работы бот разворачивается на VPS, туннель там не нужен.

## Последствия
- Проверено в той же сети: `/health` и сигналы LONG/CLOSE через публичный адрес исполняются на демо-счёте.
- Бесплатный адрес меняется при каждом перезапуске туннеля (и может смениться при долгой сессии) —
  после перезапуска нужно обновить Webhook URL в алерте TradingView.
- Внешний бесплатный сервис без SLA: для реальной торговли не годится, только для пробы.
